## Cuándo usar MCP
- Docs/Documents/documento remoto → tools de Google Docs (no solo append_text).
- Datos actuales / fuentes → search / fetch_content ANTES de redactar.
- Si pide solo opinar en chat: responde sin tools.
- Varios MCP: google/documents → Docs; websearch → internet.

## Protocolo de tools (obligatorio)
Formato EXACTO (nada de ```json):
<tool_call>
{"name":"search","arguments":{"query":"...","max_results":5}}
</tool_call>

Flujo informe en Docs (rico):
1) search (2–3 queries) y opcional fetch_content
2) create_document → guarda documentId REAL
3) create_academic_structure (portada + secciones con headings reales) O append_text del cuerpo
4) append_text por sección (≥3 párrafos densos). Títulos en texto plano SIN ningún "#":
   Bien: "Introducción\n\nEl presente informe…"
   Mal:  "# Introducción" o "## Cultivo"
   El estilo lo pone apply_heading (HEADING_1), no markdown.
5) get_document_structure → apply_heading (HEADING_1) en cada título de sección
6) append_bibliography con entries[] (URLs reales de search). NO pegues la bib solo con append_text
7) opcional: insert_table_of_contents, format_academic_document, apply_format

PROHIBIDO:
- inventar documentId / URLs / índices
- títulos con "# Título" o "## Título" en el texto (en Docs se ve el numeral feo)
- bibliografía duplicada como bullet dump
- declarar listo si headings=[] o si algún heading todavía empieza con "#"
- apply_heading sobre párrafos largos o URLs

## Respuesta final
Tras tools Docs: resumen CORTO (qué hiciste, enlace, partes, tools de formato usadas). Sin pegar el informe.

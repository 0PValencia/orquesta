# Guía de Estilo para Material Académico de Enseñanza (Temas)

## 1. Tipos de Documentos

### 1.1. Libro de Texto Académico
- **Formato**: Capítulos numerados con secciones y subsecciones
- **Profundidad**: Exhaustiva, con fundamentación teórica completa
- **Audiencia**: Investigadores y estudiantes graduados
- **Extensión**: 5,000-10,000+ líneas

### 1.2. Presentación de Diapositivas
- **Formato**: Diapositivas con viñetas concisas
- **Profundidad**: Moderada, enfocada en conceptos clave
- **Audiencia**: Estudiantes de pregrado
- **Extensión**: 100-1,200 líneas

### 1.3. Apuntes de Clase
- **Formato**: Estructura jerárquica con definiciones y diagramas
- **Profundidad**: Variable, desde básica hasta intermedia
- **Audiencia**: Estudiantes universitarios
- **Extensión**: 200-500 líneas

## 2. Estructura General

### 2.1. Para Libros de Texto

```
PORTADA
ÍNDICE
INTRODUCCIÓN

CAPÍTULO 1: [Título]
  1.1. [Subsección]
  1.2. [Subsección]
    1.2.1. [Subsubsección]
  ...

CAPÍTULO 2: [Título]
  ...

CONCLUSIONES
BIBLIOGRAFÍA
ANEXOS
```

### 2.2. Para Presentaciones

```
OBJETIVO
TEMA 1: [Título]
  - Concepto
  - Definición
  - Ejemplo
TEMA 2: [Título]
  - ...
EJERCICIOS
BIBLIOGRAFÍA
```

### 2.3. Para Apuntes de Clase

```
TEMA: [Título]
1. [Concepto]
2. [Concepto]
  2.1. [Subconcepto]
3. [Concepto]
REFERENCIAS
```

## 3. Reglas por Tipo de Contenido

### 3.1. Definiciones

**Formato estándar:**
```
[CONCEPTO]: [Definición clara y concisa]

Ejemplo: [Ejemplo práctico]

Nota: [Aclaración adicional]
```

**Reglas:**
- Usar negrita para el término definido
- Incluir siempre al menos un ejemplo
- Citar la fuente cuando sea una definición formal
- Mantener definiciones entre 2-5 oraciones

### 3.2. Clasificaciones

**Formato estándar:**
```
[CONCEPTO] se clasifica en:

1. [Categoría 1]: [Definición]
2. [Categoría 2]: [Definición]
3. [Categoría 3]: [Definición]
```

**Reglas:**
- Usar numeración para clasificaciones
- Incluir definición breve de cada categoría
- Proporcionar ejemplo de cada una

### 3.3. Procesos/Pasos

**Formato estándar:**
```
PASOS PARA [ACCIÓN]:

PASO 1: [Descripción]
  - [Detalle]
  - [Detalle]

PASO 2: [Descripción]
  - [Detalle]

...
```

**Reglas:**
- Numerar los pasos
- Incluir detalles en viñetas
- Mantener pasos entre 3-8 items

### 3.4. Comparaciones

**Formato estándar:**
```
| Característica | Opción A | Opción B |
|----------------|----------|----------|
| [Caract 1]     | [Valor]  | [Valor]  |
| [Caract 2]     | [Valor]  | [Valor]  |
```

**Reglas:**
- Usar tablas para comparaciones directas
- Incluir al menos 3 características
- Destacar diferencias clave

### 3.5. Ventajas/Desventajas

**Formato estándar:**
```
VENTAJAS:
1. [Ventaja 1]
2. [Ventaja 2]

DESVENTAJAS:
1. [Desventaja 1]
2. [Desventaja 2]

APLICACIÓN CUANDO: [Criterios de uso]
```

**Reglas:**
- Listar entre 3-6 items por categoría
- Incluir criterio de aplicación

## 4. Reglas de Formato

### 4.1. Encabezados
- **Nivel 1**: CAPÍTULO X: TÍTULO (16-18pt, negrita)
- **Nivel 2**: X.X. Título (14pt, negrita)
- **Nivel 3**: X.X.X. Título (12pt, negrita)
- Máximo 3 niveles de profundidad

### 4.2. Listas
- **Numeradas**: Para secuencias y pasos
- **Viñetas**: Para características y elementos
- Sangría consistente (2 espacios)

### 4.3. Tablas
- Encabezados en negrita
- Bordes visibles
- Contenido centrado o alineado a la izquierda

### 4.4. Fórmulas
- Numeradas al margen derecho
- Explicar cada variable
- Incluir unidades cuando aplique

### 4.5. Diagramas
- Numerados: Figura X.X
- Título debajo
- Referenciados en el texto

### 4.6. Código
- Monoespaciado
- Comentado
- Indentado

## 5. Estilo de Escritura

### 5.1. Tono
- **Académico**: Formal pero accesible
- **Explicativo**: Claridad sobre complejidad
- **Objetivo**: Sin opiniones personales

### 5.2. Persona
- **Tercera persona**: "El sistema es...", "Se define como..."
- **Primera persona del plural**: "Observamos que..." (en libros)

### 5.3. Tiempo Verbal
- **Presente**: Para definiciones y conceptos
- **Pasado**: Para historia y antecedentes
- **Futuro**: Para aplicaciones y tendencias

### 5.4. Longitud
- **Párrafos**: 3-8 oraciones
- **Oraciones**: 15-25 palabras
- **Definiciones**: 2-5 oraciones
- **Ejemplos**: 1-3 oraciones

---

## 6. Patrones de Enseñanza

### 6.1. Progresión de Complejidad
1. Definición básica
2. Ejemplo simple
3. Concepto extendido
4. Ejemplo complejo
5. Aplicación práctica

### 6.2. Análogos y Metáforas
- Usar comparaciones cotidianas
- Conectar con conocimiento previo
- Evitar jerga innecesaria

### 6.3. Repetición Espaciada
- Reintroducir conceptos clave
- Conectar capítulos anteriores
- Reforzar con ejemplos variados

### 6.4. Aprendizaje Activo
- Incluir ejercicios
- Proponer problemas
- Invitar a la reflexión

## 7. Contenido Específico por Dominio

### 7.1. Teoría General de Sistemas
- Conceptos: sistema, entorno, frontera, retroalimentación
- Jerarquías: niveles de organización
- Propiedades: sinergia, recursividad, entropía

### 7.2. Ingeniería de Software
- Modelos: cascada, espiral, PUDS
- Conceptos: requisitos, diseño, implementación, pruebas
- Herramientas: UML, lenguajes de programación

### 7.3. Calidad y Herramientas
- Diagrama de Ishikawa
- Causa-efecto
- Brainstorming

### 7.4. UML (Lenguaje Unificado de Modelado)
Fuente: presentación UML2 (96 diapositivas).
- Definición: lenguaje gráfico para requisitos, arquitectura y diseño; estandarizado por OMG.
- Tipos de diagramas: estructurales (clases, objetos, estructural compuesto, despliegue, componentes, paquetes), comportamiento (actividades, casos de uso, máquinas de estados), interacción (secuencia, comunicación, visión general, tiempos).
- Diagrama de clases: formato de clase, sintaxis de atributos y métodos, visibilidad (+ - # ~), estáticos (subrayado), abstractos (cursiva), relaciones (asociación, agregación, composición, herencia, dependencia), estereotipos, interfaces.
- Diagrama de secuencia: mensajes síncronos/asíncronos, creación/destrucción, recursión, alt/loop.
- Diagrama de actividad: acción, actividad, nodos de control (inicial, final, decisión, fusión, fork, join), swimlanes.
- Diagrama de despliegue: nodos (hardware), líneas de comunicación, artefactos.
- MDA: generación de código desde el modelo UML (OMG).

### 7.5. Diagramas de Actividad
Fuente: presentación Diagramas de Actividad (28 diapositivas) y modelonegocio.docx.
- Definición: técnica UML para describir lógica de procedimientos, procesos de negocio y flujo de trabajo; modela aspectos dinámicos.
- Diferencia clave: el diagrama de actividad describe el PROBLEMA; el diagrama de flujo describe la SOLUCIÓN.
- Elementos: inicio (círculo negro), actividad (óvalo), transición (flecha), ramificación/branch (rombo, condicional), unión/merge (rombo), fork (barra negra, ramas obligadas), fin (círculo concéntrico), andariveles/swimlanes (unidades organizacionales).
- Diagramas jerárquicos: una actividad se descompone en subactividades en un diagrama de nivel inferior.
- Ejemplos: compra de pasaje aéreo (PASAJERO/VENDEDOR/AEROLÍNEA), modelo de inscripción (cupo → formulario → examen → pago → código alumno).

### 7.6. Sistemas de Información (teoría del curso)
Fuente: presentación PERFIL DE PROYECTO Y SISTEMAS (39 diapositivas).
- Sistema: conjunto de elementos que interactúan con un objetivo común.
- Características: elementos, objetivos, entradas/proceso/salidas, subsistemas, interacción con el medio, retroalimentación, sinergia, equifinalidad.
- Subsistemas de la empresa: psicosocial, técnico, administrativo.
- Tipos de sistemas: físicos/concretos vs abstractos; cerrados (determinísticos, sin intercambio) vs abiertos (adaptativos, con intercambio).
- Premisas de la TGS: sistemas dentro de sistemas; sistemas abiertos; funciones dependen de la estructura.
- Datos vs información: dato es un hecho aislado no evaluado; información son datos organizados con significado y valor para el receptor.
- Categorías de la información: estratégica (largo plazo), táctica (control administrativo), operacional (rutinaria).
- Importancia: reduce incertidumbre; materia prima de la toma de decisiones.

### 7.7. Perfil de Proyecto (plantilla oficial del curso)
Fuente: presentación PERFIL DE PROYECTO Y SISTEMAS (diapositivas 1-4).
- Estructura del perfil: 1.1 Introducción, 1.2 Antecedentes, 1.3 Justificación, 1.4 Descripción del problema, 1.5 Formulación del problema, 1.6 Objetivos (general + específicos), 1.7 Alcance, 1.8 Entrevista.
- Plantilla de entrevista: objetivo, lugar, duración, datos de la empresa (privada/estatal), datos del entrevistado (nombre/cargo), datos del entrevistador.
- Elementos del sistema basado en computadoras: hardware (servidor, cliente, medios de comunicación, otros dispositivos), software (servidor, cliente, adicional), datos, procesos, gente/usuario, documento.
- Tecnología para el desarrollo: estrategia, metodología (PUDS, UML), herramientas de software y hardware.
- Posibles costos, beneficios (tiempo, esfuerzo, costos), posibles clientes, anexos.

## 8. Errores Comunes a Evitar

1. **Definiciones vagas**: Siempre ser específico
2. **Falta de ejemplos**: Cada concepto necesita al menos uno
3. **Saltos lógicos**: Mantener progresión clara
4. **Jerga innecesaria**: Explicar términos técnicos
5. **Falta de fuentes**: Citar referencias
6. **Exceso de texto**: Usar diagramas y tablas
7. **Inconsistencia**: Mantener formato uniforme

---

## 9. Checklist de Calidad

- [ ] Cada concepto tiene definición clara
- [ ] Cada definición tiene ejemplo
- [ ] La estructura es jerárquica y lógica
- [ ] Las referencias están en formato correcto
- [ ] Los diagramas están referenciados
- [ ] El lenguaje es claro y accesible
- [ ] No hay errores ortográficos
- [ ] El formato es consistente
